01 / SPACE

グリッドを隠さない

TiN 固有の価値は空間配置です。ウィンドウ一覧をカードとして積むのではなく、配置そのものをナビゲーションにします。選択、移動、交換が同じ座標系で理解できます。

02 / SIGNAL

状態を面ではなく光で示す

「実行中」「許可待ち」を色付きピルで埋め尽くさず、セル左端の2pxラインと小さな発光点に限定。静かな画面のまま、要対応だけが自然に浮かびます。

03 / ACTION

操作は文脈に寄せる

常時並ぶ記号ボタンを減らし、レイアウト操作は上段、選択対象の操作はInspector、横断操作は⌘Kに分離。覚える場所は3つだけです。

02 / CURRENT AUDIT

現状の評価

機能の厚みは十分です。問題は、増えた機能がほぼ同じ視覚強度で横並びになり、TiN の独自性より「AI補助機能の集合」が先に見えることです。

階層がフラット

9〜11pxの文字、淡い背景、同程度の角丸が連続し、ワークスペース・タブ・状態・操作の優先順位が読み取りづらい状態です。

記号体系が散らばる

☰ / ⊞ / ✏️ / ↺ / ⇄ / ⇅ / ◀ / ▶ / ↗ / 🎨 / ⚙ が混在。意味を学習しないと操作できず、製品としての固有言語も形成されません。

色の役割が重複

青・紫・緑・橙・黄が、アプリ種別、状態、選択、AI機能、フォーカスにまたがって使用され、色だけでは意味が確定しません。

Drawer の責務が広すぎる

Grid、Available、Memo、AI、Console が一つの縦長面に集まり、チャット型AIツールに近い「左ペインを読む」体験へ寄っています。

操作密度が常に最大

使用頻度の低い編集・反転・Space移動まで常時露出。日常操作と管理操作の区別がなく、初見時の認知負荷が高くなっています。

ブランド方針と実UIが離れている

既存の “Crystalline Void” は暗い空間、精密なグリッド、制御された発光を掲げていますが、実UIは明るい汎用SaaSの文法です。
